# Installation

Load this reference after the user requests installation, update or removal.
Consume the selected record's shared `install-options`; never recreate client
rules or invent a command for an unsupported combination. This manual workflow
does not require a marketplace checkout.

## Prepare

Resolve the canonical `bcgov-public/<type>/<name>` identity and inspect the
latest published Catalogue source repository, full SHA, path, file inventory,
digest, lifecycle, capabilities and checks. All four types may have tested
VS Code Local project choices. Non-active records have no install action.
An alias is lookup evidence only: show the canonical ID and obtain explicit
placement authority. Never automatically follow a replacement pointer.

For a published snapshot, the Catalogue's full SHA identifies its published source bytes. A development/source preview is not publication evidence. A main-based link
is latest source, may be ahead of publication, and is never pinned. The catalog
release tag is snapshot metadata, not a substitute for the selected full SHA.
No `RELEASE_TAG`-based third-party installer is advertised without layout tests.

## Place native files explicitly

1. Download the full-SHA package and compare each file's SHA-256 with the
   Catalogue file inventory. Do not execute contributed scripts or content.
2. Show the choice's client, manual installer, project scope, exact native
   source-to-destination map and evidence limits. Inspect existing files,
   directories and symlinks. Stop on a collision; do not overwrite local work
   or another Extension.
3. Ask for explicit confirmation covering this source revision and destination.
4. Copy only mapped native files. Preserve skill resources together; flatten
   single-file types as mapped. Do not copy `bcgov-extension.yaml`. Withhold an
   action for packages needing an untested resource adaptation.
5. Compare every installed native file's SHA-256 with the choice. Report exact
   paths and comparison results. A digest in a URL does not verify bytes.

Skills also have a tested personal/global choice rooted at the selected home
directory, `~/.copilot/skills/<name>/`. The other types are project-only.
No APM, npx or native deep-link action is supported by this contract. Do not claim a lockfile, runtime evaluation or client discovery result.
The tested layout contract and evidence limits are in the site's format guide.

## Update and remove

Inspect the desired published revision and compare its changes with the
previously selected Catalogue and installed bytes. Ask before replacing only
selected native files. Preserve local edits for manual review. A Specialty
transfer preserves identity but changes source path: show old/new coordinates
and require explicit migration approval. Do not silently reinterpret an alias.

For removal, use the selected revision's exact map, compare installed bytes,
then ask before deleting those files only. Preserve unrelated guidance.
Current non-active notices override new-install recommendations from older
snapshots; older affected pins need the published update/removal guidance.
