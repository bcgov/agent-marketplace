Agent Asset Formats

The BC Gov marketplace publishes four declarative asset types: skills, prompts, instructions, and agents. Every asset has a portable source package, marketplace metadata, and an author-declared compatibility note.

i
Compatibility is not certified. The marketplace validates package format and policy. It does not runtime-test each asset on each harness or compare model quality. An empty compatibility exclusion list means only that the author declared no exclusions.

Import into a harness

For VS Code Local project placements, copy the type-specific content file to the location in the table. Preserve supporting resources next to the file when the format uses relative references. Review the destination and file list before copying; importing requires an explicit user action.

Other harnesses may use different directories or formats. Skills use the shared Agent Skills format where the harness supports it. Prompts, instructions, and custom agents are not assumed to be interchangeable across products. Use the package's author-declared not-ready-on list and the harness's current documentation before importing.

Author-declared readiness

Authors may list harness identifiers under compatibility.not-ready-on in the marketplace manifest. These are author claims, not marketplace runtime-test results. Do not interpret an unlisted harness as tested or guaranteed compatible.

Tested install matrix and limits

The native-project-layout/v1 contract is exercised in CI through the shared choice builder and actual placement interface for all four rows above. Fixtures use directory-per-Extension immutable source coordinates, real byte copying, collision refusal, update/removal, explicit Specialty migration and installed hash comparisons. Skills retain their support tree; the other three types use canonical leaf-name files flattened into native directories. Marketplace validation treats contributed files as inert data.
