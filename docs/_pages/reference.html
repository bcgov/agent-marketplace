Reference

The v1 contract covers skills, instructions, prompts and agents. Package validation, declared access and automated evidence describe an exact revision. Author-declared readiness is not runtime certification.

Native formats

Packages live at <skills|instructions|prompts|agents>/<community-or-specialty>/<name>/. Each contains bcgov-extension.yaml and UTF-8 Markdown: SKILL.md, <name>.instructions.md, <name>.prompt.md or <name>.agent.md. Skill native YAML frontmatter requires name and description. Non-skill frontmatter is optional for the validated portable format; client choices impose their own native restrictions. Skills may carry resources in assets/, references/ and scripts/; optional agents/openai.yaml is not required. Contributed files remain data during marketplace validation.

Effective display name derives from Manifest display-name, native name, then directory name (1–80 non-blank characters). Summary derives from Manifest summary, then native description (1–1,024 non-blank characters); body text is not a fallback. Native constraints still apply. Native prompt/agent names may be display names; skill name matches its package directory.

Skill profile

SKILL.md begins with a closed YAML mapping: required kebab-case name (matches directory, at most 64 characters) and non-empty description (at most 1,024 characters, no angle brackets). Only name, description, owner, tags, license, allowed-tools, compatibility and metadata are allowed; owner/tags are recommended. Quote YAML values containing colon-space.

The body has an H1 and seven non-empty H2 sections in order: Use When, Don't Use When, Workflow, Rules, Examples, Edge Cases, References. Use the straight apostrophe in Don't Use When. The whole file is at most 500 lines. Resources in scripts/references/assets stay flat, one directory level deep. Cross-skill duplicate name, description or normalized body fails multi-skill validation. The repository validator supports targeted validation and --all; --no-duplicates is for deliberately isolated validation, not a publication waiver. Optional Codex metadata does not change the closed skill frontmatter profile or establish another harness's readiness.

Manifest

Only maintainers and capabilities are required. Unknown fields are rejected by the closed Manifest schema. Identity, type, Specialty and name derive from the path.

Trust & evidence

Declared access and its risk band describe author declarations. Recognized deterministic findings separately detect supported secret patterns, hidden Unicode and undeclared network/environment/script access. Detected undeclared access blocks validation; the scanner is not a complete capability analysis. Security owns the approved blocking set and fixtures. Passing automated checks is Auto-checked, with no human review implied. Marketplace reviewed requires named reviewers for the exact revision and digest; unknown review evidence stays Not recorded.

The policy route is independent of trust evidence: Specialty owning-team review, Community eligibility and lifecycle holds describe required handling, not completed review. A successful human-review route means the PR waits for review. Engine and authorization input fingerprints identify actual implementation/policy inputs, not a safety finding or granted merge authorization. Checks carry outcome, policy version and checked package digest; compare that digest with the selected package. Runtime behavior, prompt safety and model quality remain outside these claims.

Stable identity and lifecycle

Canonical identity is bcgov-public/<skill|instructions|prompt|agent>/<name>. Type/name is unique across Specialties and stays reserved on trusted main, including removed records and before publication. A Specialty-only move preserves identity and requires reviewed ownership transfer. A name/type change creates a new identity and leaves the old removed Manifest with its notice and optional moved-to. The finite Admin-owned pre-v1 alias list preserves nine published identities without guessing new aliases.

quarantined retains a visible warning and valid content, with no installation. removed is a Manifest-only tombstone including summary and notice. Hard-blocked bytes must be corrected or removed directly; quarantine cannot waive checks. Default browsing excludes non-active records; search/direct IDs retain warnings. Replacement chains retain every notice, must be finite and have existing targets, and can end active, quarantined or removed. Navigation never silently migrates or installs a replacement. Community restoration requires Admin review; Specialty restoration/transfers require the relevant owners. Admins retain takedown authority.

Source dates and four coordinates

  1. Current site: site source SHA, build run and attempt. A local build is not deployment evidence.
  2. Catalogue snapshot: CalVer tag, source SHA and exact asset digest. Source previews are labelled separately.
  3. Release: recorded release URL and actual publication time.
  4. Deployment: successful Pages event/run evidence; absent evidence stays Not recorded.

Catalogue source and site source may differ on a docs-only deployment. Source added/updated use UTC first-parent history from the retained legacy baseline, tracking package/Manifest/path changes. Unknown baseline additions stay Not recorded; these are not publication dates. Snapshot assets record exact bytes; tags alone do not prove successful release or deployment. Recovery retains current accepted data when rolling back site code. See Operations and pending live acceptance.
