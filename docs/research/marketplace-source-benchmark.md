# External Source Benchmark: Which Marketplaces Set the Standard?

**Date:** November 2026
**Scope:** First-party official agent skill/instruction/prompt/agent marketplaces and well-maintained independent registries, evaluated as of **November 2, 2026**.
**Purpose:** Compare discovery sources against the launch decision recorded in [External-source eligibility: which sources may the finder search and recommend?](https://github.com/bcgov/agent-marketplace/issues/24). The four named sources remain the v1 baseline; this report does not change their status or propose managed-settings enforcement.

---

## Methodology note: facts vs. inference vs. unverified

- **Fact [cited]** — directly observed in a primary source (official docs page, source repo file, registry page) fetched during this research session. The source URLs appear below; source-specific facts without a file-level citation should be verified before they become implementation requirements.
- **Inference** — a reasonable conclusion drawn from cited facts but not itself stated verbatim in any single source (e.g., "X likely means Y"). Explicitly labeled "Inference:".
- **Unverified / excluded** — a claim or candidate that could not be confirmed from a primary source in this session, or that turned out not to exist/not to be a marketplace in the sense this report requires. Listed in its own section below; never presented as fact elsewhere in this report.
- A branding of "official" or "Microsoft/GitHub/Anthropic-owned" is **not treated as equivalent to an independent security audit or content review** anywhere in this report. Where a source's own docs say reviews are automated/scan-based rather than human security review, that distinction is called out explicitly.

## Per-source detail

### 1. Agent Skills Directory (vercel-labs/skills + skills.sh) — *existing source*
- Repo: `github.com/vercel-labs/skills`. README states it is "The CLI for the open agent skills ecosystem," supports OpenCode, Claude Code, Codex, Cursor "and 75 more" (vercel-labs/skills:README.md, fetched via `github.com/vercel-labs/skills`).
- Install flow: `npx skills add <org>/<repo>`; discovery via `npx skills find` or the website (vercel-labs/skills:README.md "Install a Skill"/"Other Commands" sections).
- **Important nuance (fact):** the `skills.sh` leaderboard itself displays skills sourced from many unrelated third-party GitHub orgs/repos (e.g. `101-skills/superpowers` — 3.7M installs, `qu-skills/superpowers`, `microsoft/azure-skills`, `google/agents-cli`, `larksuite/cli`), observed directly on the fetched page (`https://www.skills.sh/`, fetched 2026-11-02). **Inference:** this means "Agent Skills Directory" as an approved source is better described as a *meta-aggregator of the open skills ecosystem* rather than a single curated, Vercel-reviewed catalog — i.e., its provenance guarantee is weaker/broader than "Microsoft Agent Skills" or "Anthropic Skills," which are single-publisher repos.
- Root file listing (fetched via GitHub API, commit `51b9062b3fc51dc04c89ab92dbeb65681fa0cb25`, 2026-11-02): contains `.changeset/`, `.husky/`, `AGENTS.md`, `LICENSE` (MIT), `ThirdPartyNoticeText.txt`, `docs/`, `src/`, `tests/`. **No CODEOWNERS file found** in this listing (vercel-labs/skills repo root, fetched via github-mcp-server `get_file_contents`).
- CI: `.github/workflows/agents.yml`, `ci.yml`, `publish.yml` present (vercel-labs/skills:.github/workflows/, same fetch).
- Freshness: most recent commit at fetch time is a `v1.7.5` publish-bot commit, 2026-11-02T18:20:11Z, and a merged PR #2650 same day fixing update-check regressions (vercel-labs/skills, `list_commits`, sha `51b9062b3fc51dc04c89ab92dbeb65681fa0cb25` / `dda30582047dcc5d5c37609cba5f4d11dd5954c0`).
- Revision evidence: CLI generates a `skills-lock.json`, but the independent skills.sh audit lookup is keyed by repository and slug, not the installed revision; see the [source-specific evidence research](https://github.com/bcgov/agent-marketplace/issues/23).
- Related standard: README links to `agentskills.io` as "Agent Skills Specification" (vercel-labs/skills:README.md "Related Links").
- Telemetry/security-audit note: README states the CLI "collects anonymous usage data" and performs "security-audit requests," disable-able via `DISABLE_TELEMETRY=1`/`DO_NOT_TRACK=1` (vercel-labs/skills:README.md "Telemetry"). This is a CLI-side check, not a documented per-package scanning/signing pipeline.

### 4. Awesome Copilot — *existing source*
- Repo: `github.com/github/awesome-copilot`, website `awesome-copilot.github.com` with full-text search and an `llms.txt` machine-readable index (github/awesome-copilot:README.md, fetched 2026-11-02).
- **Contribution review (fact, by far the most mature of the four existing sources):** root `CODEOWNERS` assigns ownership per path to named GitHub teams — e.g. default `@github/awesome-copilot-core-maintainers`; `/extensions/` → `@github/awesome-copilot-canvas-reviewers`; `/plugins/` and `/.github/plugin/` → `@github/awesome-copilot-plugin-reviewers`; `/agents/`, `/instructions/`, `/skills/`, `/hooks/`, `/workflows/` → `@github/awesome-copilot-content-reviewers` (github/awesome-copilot:docs/maintainers/review-routing.md, commit `61fa1fa8fcc63d6dbd2f07a75aeb8e214df5acfb`, full text fetched).
- The same document describes an **automated reviewer-routing workflow** driven by `.github/review-routing.yml`, with documented SLAs: first review due within `sla.first_review_business_days` (default 2 business days), escalation after `sla.escalation_business_days` (default 4 business days), label-based routing (`.github/workflows/label-pr-intent.yml`, `review-routing.yml`), reviewer-load balancing ("fewest open review requests"), and an hourly sweep for unrouted/overdue PRs (same file, sections "Reviewer pools," "Routing," "Failures and concurrency").
- README explicitly warns: *"The customizations here are sourced from third-party developers. Please inspect any agent and its documentation before installing"* (github/awesome-copilot:README.md "Contributing") — the project's own docs disclaim any implied security vetting beyond the review process above.
- Install: Copilot CLI/VS Code have the marketplace pre-registered; `copilot plugin install <plugin-name>@awesome-copilot`, or `copilot plugin marketplace add github/awesome-copilot` for custom setups (github/awesome-copilot:README.md "Install a Plugin"). Four content types are explicitly separated: Agents, Instructions, Skills, Plugins, plus a Cookbook (README "What's in this repo" table) — this matches BC Gov's own `extension-types: [skill, prompt, instructions, agent]` declaration for this source in `config/marketplace.yaml`.
- Freshness: most recent fetched commits dated 2026-11-02T03:40–03:52Z, including automated "[bot]" Learning Hub documentation merges and an "external-plugin" automation-approved addition (github/awesome-copilot, `list_commits`).

### 5. agentskills.io — verified to exist, but **not itself a marketplace**
- Confirmed live (fetched `https://agentskills.io/home.md`, 2026-11-02): it is the home of the **Agent Skills open specification/standard** — "Agent Skills are a lightweight, open format for extending AI agent capabilities," maintained at `github.com/agentskills/agentskills` and a Discord (agentskills.io:home.md "Open development").
- It hosts a **"Client Showcase"** (`agentskills.io/clients.md`, linked but not independently content-fetched in this session) listing which agents/products support the standard — this is a *compatibility directory*, not a skill-content registry with install/search for individual skills.
- **Classification for this report: excluded as a direct "add to approved-discovery-sources" candidate**, because it does not host or index installable Extensions the way the four existing sources do; it is the spec that several of the existing/candidate sources (vercel-labs/skills, Anthropic, VS Code docs) reference and depend on. It is, however, a useful **governance reference point** — VS Code's own docs describe Agent Skills as "an open standard" maintained at agentskills.io (code.visualstudio.com/docs/agent-customization/agent-skills, fetched 2026-11-02, "Agent Skills vs custom instructions" table row "Standard").

### 6. Claude Code Plugin Marketplaces — a *mechanism*, not a single registry
- Primary docs fetched: `code.claude.com/docs/en/plugin-marketplaces` ("Create a marketplace") and `code.claude.com/docs/en/plugins/publish.md` ("Publish and distribute a plugin"), both 2026-11-02.
- Fact: any git repo with a `.claude-plugin/marketplace.json` (fields: `name`, `owner`, `plugins[]`) becomes an installable marketplace via `claude plugin marketplace add <source>` (code.claude.com/docs/en/plugin-marketplaces, "Create the marketplace file").
- Fact: Anthropic operates a **first-party curated directory** distinct from this decentralized mechanism — docs describe "Submit to Anthropic's directory": requires "a GitHub repository holding the plugin and a paid claude.ai plan to submit from," installable by people who "add it on claude.ai or in Cowork," and syncs into Claude Code sessions via account sync, with auto-update "Yes, after the version you push is published" (code.claude.com/docs/en/plugins/publish.md, "Choose how to distribute" table).
- Revision pinning: version is either an explicit `version` field in `plugin.json`, or — if omitted — Claude Code "uses the commit SHA instead" (code.claude.com/docs/en/plugins/publish.md, "Decide how you'll version").
- Validation gate: `claude plugin validate --strict` is a **schema/structural validator** (checks required fields, path conventions), not a security scanner (code.claude.com/docs/en/plugins/publish.md, "Validate").
- **Classification:** `anthropics/skills` (an existing approved source) already uses this exact mechanism (`/plugin marketplace add anthropics/skills`, confirmed in anthropics/skills:README.md above). Anthropic's broader first-party directory (the "Submit to Anthropic's directory" destination) is a **plausible distinct future candidate** separate from the `anthropics/skills` GitHub repo, but this report could not fetch a public catalog page/API for that directory in this session — see Unverified section.

### 7. OpenAI Apps SDK / Plugin Directory — real, but in preview and architecturally different
- Primary source: `help.openai.com/en/articles/12515353-building-with-the-apps-sdk` ("Building with the Apps SDK," marked "Updated: 5 days ago" at fetch time, 2026-11-02).
- Fact: the original 2023 ChatGPT "Plugin Store" was fully discontinued — legacy plugins stopped working April 9, 2024 (per web search of OpenAI/community sources; **this specific shutdown date is secondary-sourced, not fetched from an OpenAI primary page in this session — treat as moderately-confident background, not a cited primary fact**).
- Fact: OpenAI now runs an **Apps SDK (preview)** built on MCP (Model Context Protocol), with a "ChatGPT app directory" accepting submissions: *"We are accepting app submissions... Apps that meet higher design and functionality standards may be eligible to be featured more prominently"* (help.openai.com/en/articles/12515353, "Submissions and directory").
- Fact: developer guidelines are explicitly **draft/preview** — *"these guidelines and required standards are subject to change as we learn and hear more from our developer community"* (same source, "Safety and privacy").
- **Classification:** architecturally this is an **apps/integrations marketplace** (MCP servers with UI), not a skill/instruction-markdown marketplace like the four existing BC Gov sources. It is a first-party, actively-evolving mechanism worth watching, but as of Nov 2026 it does not map to this repo's "Extension" definition (skill/instructions/prompt/agent) and its review process is explicitly still a draft. **Recommend tracking, not adding, at this time** (see Synthesis).

### 8. npm provenance — a security-signal mechanism, not a marketplace, but relevant to item #4
- Primary source: `docs.npmjs.com/generating-provenance-statements` (fetched 2026-11-02).
- Fact: npm provenance = two attestation types (provenance + publish), generated via Sigstore, requiring a supported CI/CD provider (GitHub Actions or GitLab CI/CD) with `id-token: write` permission and `npm publish --provenance`; attestations are "signed by Sigstore public good servers and logged in a public transparency ledger" (docs.npmjs.com, "About npm provenance," "About Sigstore").
- Fact, explicitly stated by npm itself and important for this report's "don't conflate official branding with security review" instruction: *"When a package in the npm registry has established provenance, it does not guarantee the package has no malicious code... provenance provides a verifiable link to the package's source code and build instructions, which developers can then audit"* (docs.npmjs.com, "Provenance limitations"). This is the single strongest, most externally-verifiable **supply-chain attestation mechanism found in this entire survey** — stronger than anything the four existing skill-specific sources document — but it attests build/source linkage, not content safety.
- The `vercel-labs/skills` CLI is itself npm-distributed (`npm install skills` / `npx skills`) per its own README and npmjs.com package page (fetched 2026-11-02) — so the *tool* that mediates the "Agent Skills Directory" source already rides on this npm infrastructure, though the badges fetched did not show a provenance checkmark in the text content retrieved.
- **Classification:** not a candidate "External source" in BC Gov's taxonomy (it's a package registry, not a skill-content marketplace), but directly relevant as a **benchmark** for dimension 4 (item security signals) that none of the four existing or other candidate sources currently match.

### 9. GitHub Marketplace (Apps) — a related-but-different first-party mechanism
- Fact: `github.com/marketplace?type=apps&query=copilot` (fetched 2026-11-02) lists 32 "apps" results for "copilot," e.g. "GitHub Copilot for Linear," "GitHub Copilot for Jira," "LaunchDarkly for GitHub Copilot" — these are **GitHub Apps/integrations** (OAuth-scoped software extensions, reviewed under GitHub's standard Marketplace App listing process), not skill/instructions/prompt Markdown content.
- **Classification: excluded** — this is a different extension category (installable software integrations, not portable instruction bundles) and does not map to this repo's "Extension" definition. Mentioned only to confirm it was checked and is not a hidden duplicate of Awesome Copilot.

## Synthesis / ranked recommendations for v1 additions *(opinion — not fact; does not change the existing four-source decision)*

This section is analysis and judgment calls by the author of this report, clearly separated from the cited facts above. **It is not a proposal to change v1** — the four existing sources' `status: active` entries in `config/marketplace.yaml` are out of scope for this report, per the user's explicit instruction.

**Ranked candidates for a possible v2 addition, by incremental coverage/credibility gained vs. risk added:**

1. **Anthropic's first-party Claude plugin directory** (the curated submission destination described in `code.claude.com/docs/en/plugins/publish.md`, distinct from the `anthropics/skills` GitHub repo already approved) — *if and when* a stable public catalog URL/API for it is confirmed. Rationale: it is first-party, uses the same commit/version pinning model already accepted for `anthropics/skills`, and would extend coverage to community Claude plugins beyond Anthropic's own demo repo — but this report could not confirm its catalog is independently browsable outside claude.ai/Cowork, so this is conditional on that gap being closed in a future research pass, not a ready-to-add recommendation today.
2. **npm's provenance mechanism as a *supply-chain reference*, not a new source** — consider provenance for any future npm-distributed installer, but do not use it as an eligibility substitute for skill content review: it attests where a package build came from, not whether the bundled or subsequently downloaded skill is safe.
3. **OpenAI's Apps SDK / Plugin Directory — track, do not add yet.** It is real and actively evolving, but (a) it is architecturally an MCP-server/app marketplace, not a skill/instructions/prompt/agent marketplace matching this repo's "Extension" definition, and (b) its own developer guidelines are explicitly labeled "draft" and "subject to change" as of the Nov 2026 help-center article. Revisit once guidelines leave draft status and if OpenAI's ecosystem produces artifacts that map cleanly onto this repo's Extension types.

**Explicitly not recommended for v2 based on this research:** agentskills.io (not a registry — it's the spec, already referenced as context by several existing sources), GitHub Marketplace Apps (wrong extension category), and any of the "Unverified / excluded" candidates above until a primary source is actually fetched and reviewed.

**One-sentence bottom line:** Among the four actual skill sources checked, **Awesome Copilot sets the clearest contribution-review benchmark**, **skills.sh sets the discovery and cross-client-install benchmark**, and **Microsoft Agent Skills provides a useful first-party, searchable catalogue**; none provides a verified, durable security audit bound to each native skill's install revision. npm provenance is a separate supply-chain benchmark, not an item-security assessment or another skill marketplace.
