# Native install and marketplace formats for bcgov/agent-marketplace

Research for [issue #11](https://github.com/bcgov/agent-marketplace/issues/11), as of 2026-10-30. “Supported” below refers to documented native *client* capabilities, not automatic understanding of this repo’s `bcgov-extension.yaml` or `catalog/catalog.json`. A declared version is not a reproducible installation; a commit SHA or lockfile is stronger.

## Required layouts and one-repo compatibility

**VS Code and Copilot CLI.** VS Code reads `.github/prompts/*.prompt.md`, `.github/instructions/*.instructions.md`, `.github/agents/*.agent.md`, and skill directories; prompt/instruction files also support a [VS Code user profile](https://code.visualstudio.com/docs/agent-customization/prompt-files), with instruction `applyTo` globs ([instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions); [agents](https://code.visualstudio.com/docs/agent-customization/custom-agents)). These are not VS Code extension-gallery `package.json` packages ([extension manifest](https://code.visualstudio.com/api/references/extension-manifest)). [Agent Plugins marketplace browsing](https://code.visualstudio.com/docs/agent-customization/agent-plugins) is separate and experimental. Copilot CLI searches for `marketplace.json` at root, `.plugin/`, `.github/plugin/`, **or `.claude-plugin/`**, in that order. Agent Plugins 1.0 requires `$schema` and `plugin.json` at plugin root; skills must be in *immediate* `skills/` subdirectories and Copilot agents/commands/rules go under `com.github.copilot/`. Legacy plugins have configurable component paths. Marketplace Git `source` objects accept optional `path`, `ref`, `sha` ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)).

**Claude Code.** `.claude-plugin/marketplace.json` has `name`, `owner` and plugin entries (`name`, `source`); sources include relative directories, GitHub/git, `git-subdir`, npm and archives. Plugin discovery expects plugin-owned `skills/`, `agents/`, `commands/`, or configured component paths in the optional plugin manifest ([marketplace](https://code.claude.com/docs/en/plugins/marketplace-reference); [components](https://code.claude.com/docs/en/plugins/components)). Always-loaded [CLAUDE.md instructions](https://code.claude.com/docs/en/memory) are *project/user configuration*, not a fourth distributable plugin component. [Commands](https://code.claude.com/docs/en/skills) are older than skills and not the same file format as VS Code `.prompt.md`.

**Shared plugin manifest, different packages.** Both CLIs discover `.claude-plugin/marketplace.json`, but the Copilot Agent Plugins standard fixes skill locations and reserves client-specific agent/command/rule locations, whereas Claude uses its own component directories. A common per-plugin `skills/<name>/SKILL.md` can serve both; add client-specific companion files separately. Do **not** claim that a manifest entry whose `source` is `skills/security` alone packages existing `skills/security/<name>/SKILL.md`: those are plugin-root children, not `skills/<name>/` under a plugin root ([Copilot components](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference#components); [Claude components](https://code.claude.com/docs/en/plugins/components)). Test an actual package with both clients before advertising one-click compatibility.

**APM.** [Package types](https://microsoft.github.io/apm/reference/package-types/) distinguish root skill bundles, multi-skill collections and `.apm/` typed primitives. The [install CLI](https://microsoft.github.io/apm/reference/cli/install/) supports `apm install -g owner/repo/path#commit`, selective `--skill` and lockfiles; it does not consume bcgov metadata as its native manifest. This repo already documents installing individual canonical `skills/community/<name>` directories via `apm install`. The documented multi-skill signal is `skills/<name>/SKILL.md`; although APM describes nested skill selectors, **whole-repository installation with this repo’s `skills/<specialty>/<name>/SKILL.md` tree has not been tested**. Avoid promising `apm install bcgov/agent-marketplace` installs every skill. `apm.yml` is only required when APM metadata/dependencies are desired ([manifest schema](https://microsoft.github.io/apm/reference/manifest-schema/)).

**Agent Skills and `npx skills`.** The [specification](https://agentskills.io/specification) defines only skill directories (`SKILL.md`, optionally `scripts/`, `references/`, `assets/`) with matching `name`/folder and required `description` frontmatter. The separate [skills CLI](https://github.com/vercel-labs/skills) finds nested directories including this repo’s category tree, installs by source and can select a skill; no publisher manifest is needed. A source `#ref` pins a tag/commit rather than a skill-version field; [`skills-lock.json`](https://github.com/vercel-labs/skills/blob/main/docs/commands.md) is consumer-side bookkeeping, not a publisher registry.

**Plain copy.** Copy a skill to `.github/skills/<name>/SKILL.md` or a supported [user skill directory](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills); instructions to `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md` or the [Copilot CLI user `$HOME/.copilot/copilot-instructions.md`/`instructions/`](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions). VS Code prompts go to `.github/prompts/*.prompt.md` or its user profile, agents to `.github/agents/*.agent.md` ([VS Code agents](https://code.visualstudio.com/docs/agent-customization/custom-agents)). Claude user locations include `~/.claude/CLAUDE.md`, `~/.claude/skills/`, `~/.claude/agents/` and legacy `~/.claude/commands/` ([memory](https://code.claude.com/docs/en/memory); [skills](https://code.claude.com/docs/en/skills); [subagents](https://code.claude.com/docs/en/sub-agents)). GitHub web/IDE/CLI support **differs**: `.github/prompts` is a VS Code convention, not a universal GitHub.com prompt marketplace ([feature matrix](https://docs.github.com/en/copilot/reference/copilot-feature-matrix)). Copying has no update contract or automatic provenance.

## Recommended formats and minimal layout

1. **Keep the canonical publisher tree** `skills/<specialty>/<name>/{SKILL.md,bcgov-extension.yaml}` and generated `catalog/catalog.json`. This already serves Agent Skills and `npx skills add bcgov/agent-marketplace`; the documented **per-skill** `apm install -g bcgov/agent-marketplace/skills/<specialty>/<name>#<commit>` stays the APM path. Neither installer interprets bcgov catalog metadata as a native manifest. Existing skills are the *only currently implemented type*: author/validate instructions, prompt and agent content before advertising those types ([repository README](https://github.com/bcgov/agent-marketplace/blob/main/README.md); [APM install](https://microsoft.github.io/apm/reference/cli/install/)).
2. **Add a plugin adapter only after validating both CLIs:** one `.claude-plugin/marketplace.json` pointing at installable per-plugin roots, each containing `skills/<name>/SKILL.md` (plus Copilot `plugin.json`/`com.github.copilot/{agents,commands,rules}` and Claude `agents/`, `commands/` where appropriate). Generate/copy thin package overlays from canonical content rather than moving the canonical tree; a manifest alone pointing to current specialty dirs is **insufficient**. Pin plugin sources to full commit SHAs where reproducibility is needed; update pins when publishing ([Copilot reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference); [Claude reference](https://code.claude.com/docs/en/plugins/marketplace-reference)).
3. **Offer manual `.github/`/user-level copy as a fallback** once all four types have content. Treat VS Code’s experimental Agent Plugins UI as an opportunistic consumer of the same manifest, **not** a separate required publisher format ([VS Code plugins](https://code.visualstudio.com/docs/agent-customization/agent-plugins)).

**Bottom line:** One repository can serve several formats without replacing bcgov’s canonical metadata, but plugin marketplaces require real packaging overlays and type-specific adapters; current files serve skill installs only.
